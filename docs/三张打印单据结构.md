# 三张打印单据的真实结构

来源：用户提供的系统导出文件（`入库单记录参考`、`出库单记录参考`、`送货单参考`），各含多个工作表，每表一张单据。
这三张表是判断新系统字段与打印需求的第一手依据，**优先级高于从网页表单推测的结论**。

---

## 一、入库单（供应商 → 我方）

| 位置 | 字段 |
|---|---|
| 抬头 | 标题「河南万楼商贸有限公司入库单」 |
| 表头 | 入库单编号、供应商名称、采购合同号、备注 |
| 明细列 | 序号、产品、型号、数量、单位、**单价（不含税）**、**总价（不含税）**、备注、入库仓库 |
| 合计行 | 数量合计、总价合计 |
| 页脚 | 发起人 + 日期 |

**关键观察**：入库单打印**只出现不含税价**，没有含税价，税率不上单据；明细行带「入库仓库」和「行备注」；「产品」列写的其实是「品牌 + 名称」的拼接，与「型号」列经常重复（例：产品「沃尔10kV单芯冷缩户内终端1*70-120」、型号同字符串）。

## 二、出库单（我方 → 客户）

| 位置 | 字段 |
|---|---|
| 抬头 | 标题「河南万楼商贸有限公司出库单」 |
| 表头 | 出库单编号、销售员、客户名称、销售合同号、**发货地址与收货人信息**（多行）、物流公司、其他信息 |
| 明细列 | 序号、产品、型号、数量、单位、备注、出库仓库 |
| 合计行 | 合计（数量） |
| 页脚 | 发起人 + 日期、**审核人 + 日期** |

**关键观察**：出库单打印**完全没有价格**，只有数量——这是给客户看的随货单据，价格属于商业秘密。收货地址是自由文本多行，含姓名和手机号。页脚同时记录发起人和审核人，说明双人留痕是硬需求。

## 三、送货单（仓库 → 承运人/客户签收）

| 位置 | 字段 |
|---|---|
| 抬头 | 标题「河南万楼商贸有限公司送货单」 |
| 表头 | 收货单位、承运人（快递/京东）、收货地址（多行）、合同号、其他备注 |
| 明细列 | 序号、产品、**品牌**、型号、数量、单位、备注 |
| 页脚 | 「若您对上述货物验收无误，请在此签名：」 |

**关键观察**：送货单比出库单**多了「品牌」列**，说明司机和客户需要看品牌区分货物；同样没有价格；末尾是签收栏，属于法律凭证性质。

---

## 四、对方案的修正

### 4.1 打印必须做三套模板，不能共用
- 入库单：带不含税单价与总价，带入库仓库
- 出库单：**不带任何价格**，带收货信息、物流、发起人与审核人双签名
- 送货单：带品牌，不带价格，带签收栏

### 4.2 「产品」字段需要拆分
老系统把「品牌 + 名称」塞进「产品」一列，导致与「型号」重复、无法检索。新系统应拆成：品牌、品名、型号、规格 四个独立字段，打印时再按模板拼接。

### 4.3 收货信息需要结构化
出库单里「发货地址、收货人信息」目前是一段自由文本（含姓名、手机、地址混在一起）。新系统应拆为：收货人、手机号、地址，打印时可合并显示，同时能用于后续物流对接。

### 4.4 明细行备注与仓库要保留
入库单明细每行都有「入库仓库」和「备注」，说明存在**一单多仓**或**分仓入库**的实际需求。新系统明细行需保留 `仓库` 与 `行备注` 两个字段。

### 4.5 单据号长度
实际单号是 22 位：`hnwlo` + `00005` + `20261021` + `02711`。新系统需保留同长度或做兼容映射，避免迁移后打印与对账对不上。

## 五、仍待确认的问题

1. 出库单打给客户时不带价格，那客户对账用什么单据？（销售合同？对账单？）
2. 送货单的「承运人」是手填还是从物流单号自动带出？
3. 入库单的「产品」列与「型号」列内容重复，是录入习惯还是系统自动拼接？影响迁移时字段拆分规则。
4. 是否有**退货单**的打印模板？（系统里有入库退货、出库退货，但未提供模板）
