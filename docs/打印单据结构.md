# 打印单据结构（五套模板）

来源：用户从老系统导出的真实单据文件，存放在 `data/templates/`。
这是判断字段与打印需求的第一手依据，**优先级高于从网页表单推测的结论**。

> 已确认（2026-10-23，用户原话）：出库单是**我们自己用**的单据，应当带销售价格；最高权限还能看到成本和利润，普通权限看不到成本和利润。送货单上的承运人由系统内填写（如京东快递），打印时带出。

---

## 一、入库单

`data/templates/入库单打印样本.xlsx`

| 位置 | 字段 |
|---|---|
| 抬头 | 河南万楼商贸有限公司入库单 |
| 表头 | 入库单编号、供应商名称、采购合同号、备注 |
| 明细列 | 序号、产品、型号、数量、单位、**单价（不含税）**、**总价（不含税）**、备注、入库仓库 |
| 合计行 | 数量合计、总价合计 |
| 页脚 | 发起人 + 日期 |

打印只出现不含税价，税率不上单据。明细行带「入库仓库」和行备注，说明一单可能分仓入库。

## 二、入库退货单

`data/templates/入库退货单.xlsx`

结构与入库单几乎相同，表头同样带**原入库单编号**、供应商、采购合同号、备注；页脚增加审核人。

| 位置 | 字段 |
|---|---|
| 表头 | 入库单编号（原单）、供应商名称、采购合同号、备注 |
| 明细列 | 序号、产品、型号、数量、单位、单价（不含税）、总价（不含税）、备注、入库仓库 |
| 合计行 | 数量合计、总价合计 |
| 页脚 | 发起人 + 日期、**审核人 + 日期** |

**关键观察：退货数量与金额都是负数**（例：数量 -6，总价 -42,238.94；合计 -18 与 -68,323.90）。老系统用「负数冲减」而不是新建独立金额体系。新系统应保留这个习惯：退货单冲减原单，库存与成本按负数回滚。

## 三、出库单

`data/templates/出库单打印样本.xlsx`

| 位置 | 字段 |
|---|---|
| 抬头 | 河南万楼商贸有限公司出库单 |
| 表头 | 出库单编号、销售员、客户名称、销售合同号、**发货地址与收货人信息**（多行）、物流公司、其他信息 |
| 明细列 | 序号、产品、型号、数量、单位、备注、出库仓库 |
| 合计行 | 合计（数量） |
| 页脚 | 发起人 + 日期、**审核人 + 日期** |

**注意**：老系统的打印模板不含价格，但用户明确说这是缺陷——出库单是内部单据，应带销售价。新系统出库单打印**要加价格列**，且按权限区分：普通销售看不到成本与利润，最高权限能看到成本列、毛利与毛利率。

## 四、出库退货单

`data/templates/出库退货单.xlsx`

结构同出库单，表头带原出库单编号、销售员、客户、销售合同号、收货信息、物流公司；页脚有审核人。数量为负数（例：-60 包）。

## 五、送货单

`data/templates/送货单打印样本.xlsx`

| 位置 | 字段 |
|---|---|
| 抬头 | 河南万楼商贸有限公司送货单 |
| 表头 | 收货单位、**承运人**（系统中填写，如京东快递）、收货地址（多行）、合同号、其他备注 |
| 明细列 | 序号、产品、**品牌**、型号、数量、单位、备注 |
| 页脚 | 「若您对上述货物验收无误，请在此签名：」 |

送货单比出库单**多「品牌」列**，且末尾是签收栏，属于法律凭证。承运人不在打印时手填，而是随单据带出。

---

## 六、字段设计结论

**表头字段**：单据编号、日期、仓库、往来单位（供应商/客户）、合同号、销售员、**承运人**、收货人、收货电话、收货地址、备注、发起人、审核人。收货信息拆成三列（收货人 / 电话 / 地址），打印时合并显示，便于后续对接物流。

**明细字段**：品牌、品名、型号、规格、单位、数量（退货为负）、含税单价、含税总价、不含税单价、不含税总价、仓库、行备注。老系统把「品牌+品名」拼成一列导致与型号重复，新系统拆开。

**权限分层**：默认可见含税价与金额；成本价、毛利、毛利率仅最高权限可见。打印时按权限决定是否输出成本列。

**单据编号**：22 位（`hnwlo` + 企业码 + 日期 + 序号），迁移与打印需保持一致，避免对账对不上。
