## 三、状态机与枚举（已确认）

- 出库/入库单状态：`0 待审核` → `审核通过` / `审核驳回`

## 五、老系统的问题与可优化点

**结构性缺失**
1. 没有采购订单、销售订单模块，合同只作为文本字段，无法跟踪「下了单没到货」「客户订了没发货」。
2. 没有批次/序列号/保质期管理——电缆附件这类产品若涉及厂家批次追溯会缺失。
3. 只有 1 个仓库，多仓调拨不存在（要扩仓必须先补调拨单）。
4. 无采购应付、无付款单，钱只记了「收」，没记「付」。
5. 无盘点单，库存调整只能靠「其他入库/其他出库」凑，账实差异无法归因。

**体验与性能**
6. 列表页全量渲染：客户 1355 条、物料 929 条、入库单 1217 条一次性吐在 HTML 里（页面 1.8 MB），手机端和弱网基本卡死。新系统必须改服务端分页 + 搜索。
7. 明细行用下拉框选「物料编号」和「型号」两列，选一次物料要动两次；应改为一次搜索（编号/名称/型号/品牌都能搜）自动带出其余字段。
8. 库存归属挂在明细行上，导致同一商品多归属要拆行，报表口径复杂。
9. 客户级别只有两级且手工填，实际作用有限；也没有接价格体系（客户等级价、最近成交价），每次都要手动填单价。
10. 「滞留库存」「待结转」「成本调整」三张报表当前全为空，说明流程没有真正跑通或口径没人用。

**权限与安全**
11. 密码规则：员工手机号即初始密码，登录密码 123456 级别，公网暴露，风险高。
12. 权限是「角色 × 模块 × 七种操作」的粗粒度矩阵，没有数据级隔离（比如销售只能看自己的客户）。

## 六、新系统方案

### 6.1 增删建议

**保留（骨架不动）**：基础资料（物料/客户/供应商/仓库/单位/角色/用户/部门）、入库单、出库单、两类退货、在途库存、锁库、库存实时查询、收发存汇总、成本明细、应收报表、审批流、单据编码规则、多税率与含税/不含税双价、库存归属（改成「备货人」独立字段）、项目标签。

**删除/合并**：团队管理（与部门重复，无数据）、滞留库存报表与待结转清单（口径重叠，合并为「库存健康度」一张）、成本调整表并入采购发票核对页。

**新增**：
- 采购订单 + 销售订单（含「订单 → 入库/出库」的转单与未完成量跟踪）
- 盘点单（盘盈盘亏自动生成调整单，留原因）
- 付款单/应付账款（补齐资金链另一半）
- 客户价格体系（等级价 + 最近成交价，开单自动带价）
- 批次/序列号（可选开关，按品类启用）
- 库存预警工作台（首页看板：低于最低库存、超最高库存、超期应收、待审核单据）
- 服务端分页 + 全局搜索（编号/名称/型号/客户名/手机号）
- 手机端适配（库管扫单、销售查库存与应收）
- 操作日志与单据反审核留痕

### 6.2 实施阶段

**阶段 0：原型（1–2 轮对话）**
用假数据做可点击的 HTML 原型，跑通三条主线：① 新增出库单（选客户→搜商品→填数量价格→自动算含税/不含税→提交→审核→扣库存）；② 库存查询与收发存汇总；③ 客户与商品档案维护。你在原型上直接指出多余/缺失字段。

**阶段 1：数据模型与迁移**
建库（MySQL/PostgreSQL），按第四节体量设计索；把老系统的物料、客户、供应商、期初库存、历史单据导入。迁移脚本先跑在副本上，逐表比对条数与金额合计。

**阶段 2：主流程开发**
登录权限 → 基础资料 → 入库/出库 → 审批流 → 库存计算（移动加权）→ 报表。每完成一块你用真实业务抽样核对。

**阶段 3：并行验证与切换**
与老系统并行两周，每天比对库存数量、应收余额、毛利；差异清零后切换，老系统只读保留。

### 6.3 开工前需要你确认的四件事

1. **用户数**：现在 7 个员工，新系统是否都开账号？权限要不要细到「销售只看自己的客户」？
2. **手机端**：库管是否需要在仓库用手机扫码/开单？这决定要不要做 PWA 或小程序。
3. **部署位置**：放你们自己的电脑/局域网，还是云服务器？涉及域名、备份、外网访问。
4. **数据迁移**：老系统 1200+ 入库单、100 万级条码数据要不要全部迁？还是只迁期初库存 + 客户档案，历史单据留在老系统查询？

## 七、技术选型建议（待你确认后细化）
