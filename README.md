# 万楼进销存系统

河南万楼商贸有限公司的进销存系统，替代原 SUM 进销存（psi.sumdz.cn）。

## 快速开始

### 第一次使用

1. 安装 Node.js 18 或更高版本：https://nodejs.org （下载 LTS 版，一路下一步）
2. 双击 `启动系统.bat`
3. 浏览器打开 http://localhost:3000
4. 用超级管理员登录：账号 `admin`，密码 `admin123`
5. **登录后第一件事：进「我的账号」修改密码**

关闭命令行窗口即停止服务。

### 局域网内其他电脑访问

启动窗口里会显示一个类似 `局域网访问 http://192.168.1.100:3000` 的地址，
把这一行发给同事，他们在浏览器里打开就能用。

如果打不开，检查：

- 这台电脑的防火墙是否允许 Node.js 接收连接
- 两台电脑是否在同一个路由器下

### 换电脑 / 备份

「系统设置 → 数据备份 → 立即下载备份」会下载一个 `wanlou.db` 文件，
这就是全部数据。换电脑时把它放到新电脑的 `data/` 目录下即可。

## 系统结构

```
src/
  server/
    server.js          启动入口
    db.js              数据库表结构与初始数据
    http-framework.js  路由、会话、权限校验
    routes/
      auth.js          登录、改密码
      users.js         员工管理、角色权限
      base.js          客户、供应商、物料、仓库
      docs.js          出入库、退货、审批、作废、收付款
      checks.js        库存盘点
      inventory-reports.js  库存查询、流水、各类报表
  web/                 浏览器端页面
data/
  wanlou.db            数据库文件（自动生成）
docs/                  需求与设计文档
test/
  flow-test.js         端到端业务流程测试
```

## 技术选型

- 后端：Node.js 原生 http，零第三方依赖（不需要 npm install）
- 数据库：SQLite（Node 内置 node:sqlite）
- 前端：原生 JavaScript 单页应用，无需构建
- 部署：本地单机，局域网访问；后续可迁到云服务器

没有第三方依赖是刻意的选择：不会因为版本升级挂掉，也不需要在客户电脑上联网装包。

## 已实现的功能

### 用户与权限

- 默认超级管理员 `admin / admin123`，首次登录提示改密码
- 超级管理员可新增员工、设定初始密码、分配角色、重置密码、停用账号
- 五种角色：销售员、采购员、财务、主管、超级管理员
- 角色权限可在「角色权限」页面逐项勾选，保存后立即生效
- 操作日志记录登录、增删改、审核、作废等关键动作

### 权限边界（重要）

| 能力 | 销售员 | 采购员 | 财务 | 主管 | 超管 |
|---|---|---|---|---|---|
| 看成本与毛利 | 否 | 否 | 是 | 是 | 是 |
| 看利润报表 | 否 | 否 | 是 | 是 | 是 |
| 审核单据 | 否 | 否 | 否 | 是 | 是 |
| 删除客户/供应商/物料 | 否 | 否 | 否 | 否 | 是 |
| 作废已审核单据 | 否 | 否 | 否 | 否 | 是 |
| 管理员工与权限 | 否 | 否 | 否 | 否 | 是 |

成本字段在接口层就被剔除，不是前端藏起来。销售员即使直接调接口也拿不到成本价。

销售员只能看到自己负责的客户和单据，采购员只能看到自己的入库单与供应商。

### 单据

- **入库单**：选择供应商、仓库，录明细，提交后进审批流
- **出库单**：选择客户、仓库，录明细，支持胶带分切，记录承运人与收货信息
- **销售退货**：库存回补，可关联原出库单
- **采购退货**：库存扣减，可关联原入库单
- **审批流**：草稿 → 待审核 → 审核通过（此时才动库存）或驳回（退回草稿）
- **作废**：仅超管，作废后库存自动回滚
- **收付款**：按单据登记，自动计算未结清余额与结算状态

### 胶带分切

这是这套系统区别于通用进销存的地方：

- 母卷物料设置原始宽度（如 1200mm）、分切费、料头阈值
- 出库时填写切取宽度和卷数，系统按「宽度 × 卷数」扣减母卷可用宽度
- 每支母卷单独记账，能查到每支用了多少、还剩多少
- 剩余宽度低于阈值自动标记为料头，不能再切
- 子卷物料在第一次分切时自动建档，成本 = 母卷成本 × 宽度占比 + 分切费
- 客户退回的子卷回到子卷库存，不会回到母卷

### 库存与报表

- **库存查询**：按仓库、类型筛选，母卷显示支数与可用总宽，可看每支明细
- **库存流水**：每次变动都记录，可追溯到来源单据
- **库存盘点**：自动带出账面数，填实盘，审核后按差异调整库存
- **待结转库存清单**：已出库订单的销售额、成本、毛利、毛利率，支持按期间筛选和导出
- **进销存汇总**：按物料的期初、入库、出库、期末
- **利润分析**：按客户 / 物料 / 销售员三个维度统计毛利
- **应收应付**：按客户和供应商汇总欠款余额

所有报表都能导出 CSV，Excel 可直接打开。

## 运行测试

```bash
node test/flow-test.js
```

会跑一遍完整业务流程：建仓库客户供应商物料 → 入库审核 → 出库分切审核 → 校验库存与成本 → 退货 → 作废回滚 → 验证销售员权限隔离。

## 尚未实现

这些是需求里确认过、但这一版没做的：

- 老系统 Excel 数据导入（导入模板与校验逻辑待做）
- 单据打印（出库单、送货单、退货单的纸质模板）
- 数据恢复（目前只有备份下载，恢复需手动替换 db 文件）
- 库存调拨（单仓库阶段用不上，多仓库时再做）
- 手机扫码出入库

## 环境要求

- Node.js 18+（推荐 22 LTS）
- 浏览器：Chrome / Edge / Safari 现代版本
- 单机运行最低 2GB 内存，数据量在十万条单据内 SQLite 完全够用
